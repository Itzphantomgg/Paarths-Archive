# Project Skills & Capabilities: Paarth's Archive

## 1. Project Purpose
"Paarth's Archive" is a private personal storytelling vault, living autobiography, and digital memory archive. It is designed with a monochrome cinematic aesthetic, editorial luxury feel, high-contrast serif typography, and contemplative film-first pacing inspired by vintage editorial and 35mm film photography.

### Core Guiding Principle: Private by Default
Unlike public blogs or social platforms, Paarth's Archive is sealed by default. Unauthenticated visitors cannot browse personal memories, view story cards, query search indices, or access personal timelines. The public surface consists strictly of a split cinematic hero, conceptual lore, thematic volume overviews, and an archivist entry portal.

---

## 2. Technology Stack
- **Framework**: Next.js 16 (App Router, Turbopack)
- **Language**: TypeScript (Strict mode enabled)
- **Styling**: Tailwind CSS with `@tailwindcss/typography`, custom cinematic animations, and procedural 35mm film grain
- **Database Layer**: Prisma ORM with SQLite (zero-config local relational DB + Vercel `/tmp` persistence) and PostgreSQL mirror schema (`supabase/schema.sql`)
- **Authentication**: Custom session-based auth with `bcryptjs` password hashing, `jose` signed JWT httpOnly cookies (`archive_session`), and route protection in `src/middleware.ts`
- **Sharing Architecture**: Cryptographically secure 32-character hex tokens with instant revocation
- **Icons**: Lucide React
- **Audio**: Web Audio API synthesizer for optional analog tape hiss / vinyl warmth without external audio assets

## 4. Authentication & User Isolation Architecture
- **Provider**: Supabase Auth (Single Source of Truth).
- **Authentication Methods**:
  - **Google OAuth**: One-click authentication with callback exchange (`/auth/callback`).
  - **Email + Password**: Real user registration, login, and email verification.
  - **Password Recovery**: Secure password reset flow via email dispatch (`/auth/reset-password`).
- **Session Management**: `@supabase/ssr` cookie-based sessions refreshed on each request via `src/middleware.ts`.
- **User Isolation**:
  - Every authenticated Supabase user is uniquely identified by their Supabase UUID (`auth.uid()`).
  - Stories are tied directly to `authorId = supabase_user.id`.
  - Database queries strictly enforce `where: { authorId: user.id }`.
  - User A can never browse, search, edit, share, or delete User B's stories.
- **Route Protection**: `src/middleware.ts` guards all `/admin/*` routes, redirecting unauthenticated visitors to `/login?redirect=<path>`.
- **Client Navigation**: Automatically reflects user state via `/api/auth/me`.

## 5. Story Privacy & Access Control Model

### Three Story States:
1. **`PRIVATE` (Default)**:
   - Only the authenticated owner can access.
   - Hidden from public feeds, search, and homepage.
   - Direct slug access (`/story/[slug]`) yields 404 for unauthenticated visitors.
2. **`SHARED`**:
   - Owner can access in their dashboard/editor.
   - Anyone possessing the unguessable private share link (`/shared/<token>`) can read that specific story.
   - **Zero Archive Leakage**: The shared story view exposes no pagination, chapter links, or author dashboard.
3. **`REVOKED`**:
   - Owner explicitly revokes sharing.
   - The private share link (`/shared/<token>`) immediately ceases to display content, rendering a "Dispatch Revoked / Sealed" screen.

## 6. Database Architecture
- Relational schema defined in `prisma/schema.prisma`.
- Models:
  - `User`: Archivist credentials, role, metadata.
  - `Chapter`: Sequential volumes (`01 CHILDHOOD`, `02 GROWING UP`, etc.).
  - `Story`: Rich narrative entries with `status` (`DRAFT`, `PRIVATE`), `shareStatus` (`PRIVATE`, `SHARED`, `REVOKED`), `shareToken`, `sharedAt`, `shareRevokedAt`, dates, locations, mood, people, and Markdown content.
  - `Tag` & `StoryTag`: Categorization tags.
- For local dev: reads from `prisma/dev.db`.
- For Vercel Serverless: `src/lib/db.ts` automatically copies the bundled seed DB to `/tmp/archive.db` if `DATABASE_URL` is not pointing to an external PostgreSQL instance, preventing read-only filesystem errors (`EROFS`).

## 7. Rules for Future Modifications
1. **Stories are PRIVATE by default**: Never expose stories publicly without explicit, token-based sharing.
2. **Never commit passwords or real secrets**: Keep `.env` and `.env.local` ignored.
3. **Never display dummy passwords in UI or documentation**: Authentication forms must use generic placeholders.
4. **Preserve the visual aesthetic**: Maintain deep black backgrounds (`#050505`), thin 1px borders (`border-white/10`), high-contrast editorial serif headlines, and generous whitespace.
5. **No gaming or distracting imagery**: Hero background must remain pure dark atmospheric depth with film grain and subtle vignettes.
6. **Preserve Next.js App Router conventions**: Unpack dynamic parameters asynchronously (`await params`, `await searchParams`, `await cookies()`).
7. **Always verify with production build**: Run `npm run build` to ensure type safety and route compilation.
